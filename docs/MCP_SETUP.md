# MCP_TOKEN 配置指引

本项目调用麦当劳中国 MCP Server（`https://mcp.mcd.cn`）需要一枚 MCP Token。
按项目铁律，**Token 只能存在于云函数 `mcp-proxy` 的环境变量 `MCP_TOKEN` 中**：
不进代码、不进仓库、不进日志、不进前端、不进任何本地文件。

全流程四步，约 3 分钟。

---

## 步骤 1：申请 MCP Token

1. 打开麦当劳中国 MCP Server 开放平台：**https://open.mcd.cn/mcp**
2. 点右上角【登录】，用**手机号 + 验证码**登录
3. 登录后右上角按钮变成【控制台】，点开
4. 在控制台弹窗里点【激活】，申请 MCP Token
5. 阅读并同意服务协议
6. 申请成功后页面会显示 Token，**点一键复制**

> 如官网界面与上述步骤有出入，**以官方页面为准**（本项目不复制、不转述官方页面未明确的内容）。
>
> 官方注意事项（摘自官方文档）：
> - 每个 Token **每分钟最多 600 次请求**，超限返回 `429`
> - 请妥善保管 Token，避免泄露给他人
> - 使用须遵守麦当劳中国《使用条款》及《麦当劳 MCP 服务规则》

---

## 步骤 2：在云开发控制台配置环境变量

> 与配置 `MY_ENV_ID` 是**同一个位置**。

1. 微信开发者工具 → 点工具栏上的**云开发**按钮（云朵图标）→ 打开云开发控制台
2. 左侧菜单点「**云函数**」
3. 在函数列表里点「**mcp-proxy**」→ 进入函数详情
4. 切到「**配置**」标签 → 找到「**环境变量**」
5. 新增一条记录：

   | 变量名 | 值 |
   |---|---|
   | `MCP_TOKEN` | 粘贴你复制的 Token |

6. **保存**

### 填写规范（配错会直接 401，务必逐条对照）

- 变量名严格为 `MCP_TOKEN`，全大写 + 下划线，前后无空格
- 值**只粘贴 Token 本体**：
  - ❌ 不要带 `Bearer ` 前缀（代码里会自动加 `Authorization: Bearer <token>`）
  - ❌ 不要加英文/中文引号：`"abc"` 是错的，`abc` 才对
  - ❌ 不要带首尾空格或换行（从网页复制常常会多带一个空格，建议粘贴后手动检查一遍）
- 三个云函数中**只有 `mcp-proxy` 需要配** `MCP_TOKEN`；`chat-parse`、`order-service` 不需要

---

## 步骤 3：重新部署云函数

改完环境变量，运行中的实例可能仍持有旧配置，需要重新部署一次才生效。

**这一步由实施方（AI 搭档）执行**，你无需操作。

---

## 步骤 4：自检确认

项目内置了一个只读自检入口 `action = 'mcp.status'`，用于确认 Token 是否真的生效。

它的返回体被限制为固定字段，**绝不回传 Token 本身、长度或任何片段**：

| 情况 | 返回 |
|---|---|
| Token 已配且有效 | `{ ok:true, mock:false, hasToken:true, handshake:'ok', toolCount:34, ... }` |
| Token 未配 | `{ ok:true, mock:true, hasToken:false, handshake:'skipped', toolCount:0, ... }` |
| Token 无效/过期 | `{ ok:false, code:'401', error:'MCP 凭证无效或已过期，请重新配置 MCP_TOKEN' }` |

**你不需要把 Token 发给任何人**，包括不需要发给我。是否配好由上面这个自检结果判定。

## 可选环境变量

| 变量名 | 默认 | 说明 |
|---|---|---|
| `MY_ENV_ID` | — | 云环境 ID，`ping` 自检读取（已配置） |
| `QUERY_ONLY_MODE` | 未配置 = 拦截真实下单 | 设为 `false` 才允许真实下单。**建议在下单链路联调完成前保持不配置** |
| `ENABLE_MOCK` | `true` | 无 Token 时是否回落离线演示数据。设为 `false` 则**不静默降级**，缺 Token 时直接报错，避免「以为在跑真实接口、其实在看演示数据」 |

---

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 自检返回 `code:'401'` | Token 无效、过期、或值里混入了引号/空格/`Bearer ` 前缀 | 回步骤 2 重填，保存后重新部署 |
| 自检返回 `hasToken:false` | 环境变量名拼错，或加到了别的云函数上 | 确认函数是 `mcp-proxy`、变量名是 `MCP_TOKEN` |
| 改完仍返回旧结果 | 未重新部署，实例还拿着旧配置 | 重新部署一次 |
| 返回 `code:'429'` | 超过官方限制 600 次/分钟 | 降低调用频率，稍后重试 |

---

## 安全约定（不可绕过）

- 仓库、代码、日志、前端页面中**不得出现任何真实 Token**
- 本地开发若需临时配置，使用 `.env`（已被 `.gitignore` 排除）；**不要**写进 `mcp-config.example.json` 等会入库的文件
- 前端禁止 `wx.request` 直连 `https://mcp.mcd.cn`，一切必须经云函数 `mcp-proxy` 中转
- 遇到 `401` **不重试**，直接报错并提示重新配置凭证
